## 2026-10-12 10:00–10:25 — Fetching jobs stopped when the app went to the background

The user reported (from the phone) that fetching jobs stops when the app goes to the background.
- **Cause.** The service runs the search in its own thread no matter what the client does, and keeps the finished run until the next start. The app's `search()` polled `/search/<id>` every 2 s, and any failed poll threw and ended the search with an error. In the background Android freezes cached apps or cuts their network, so the next poll timed out (20 s) or got a ClientException. Nothing picked the run back up on resume, and the run id was never stored, so a relaunch couldn't either.
- **Fix (uncommitted).** `lib/api.dart`: `ServiceUnavailable` (prints as `Exception: …`) for timeouts, ClientException and non-JSON 5xx (the Tailscale proxy's 502 while the service is down). `lib/main.dart`: `search()` → `collect(id)`. A new search stores its id in prefs `search_run` (`rememberRun`). A `ServiceUnavailable` poll waits on a `backOnScreen` completer while the lifecycle is hidden/paused/detached. On screen it retries and gives up after 3 misses in a row, keeping the id. Resume runs `collect(searchRun)` when idle, and so does `load()` (relaunch). Complete, error status, 404 expired and the 20-min deadline clear the id. Before formatting, I extracted the pre-edit main.dart from the 09:49 test dill (`build/test_cache/...track.dill` embeds sources) and diffed it: dart format changed only my hunks.
- **Checks.** New `test/background_search_test.dart` (4 tests: waits in background then finishes on resume, collected on relaunch, expired dropped, gives up on screen but keeps the id) and an api_test case. 57 Flutter tests pass, analyze clean. Backend unchanged, so no restart.
