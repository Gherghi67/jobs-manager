# CV tailoring inside Fieldwork (phone app and website)

## Primary Request and Intent

The user asked (7 Nov 2026, via `/branch-out`): "a feature for the phone and app, basically, to have a llm builtin where you can tailor your cv using the cv-tailoring skill". The skill they mean is **resume-tailoring** (no skill is named cv-tailoring). Goal: from the Android app and the website, pick a job (from search results, Saved, Applied, or a pasted posting URL/text) and get a tailored CV built by an LLM that follows that skill and the user's CV rules, then download/open the PDF on the device.

Scope questions to settle with the user before building (ask, don't assume): the entry point (a button on a job card/details, a dedicated tab, or the existing Claude page with a preset); whether the conversational "branching experience discovery" of the skill runs as a chat on the phone or is skipped; and whether the result is only a PDF or also cover-letter/answer drafts.

## Key Technical Concepts

- **Fieldwork** = Flutter client shared by Android and the web (`lib/`), plus a standard-library Python service (`backend/service.py`) on the user's Mac, reached over Tailscale Serve (private tailnet HTTPS). Bearer token in `backend/.access-token`. The website is served by the same service from gitignored `build/web` (`scripts/build_web.sh`); APKs ship through `scripts/build_apk.sh` and the in-app updater.
- **The Claude page already exists** and is the natural base: `backend/claude_chat.py` + `lib/claude_chat.dart`. It runs `claude -p` with `--permission-mode auto --permission-prompts none` (never bypassPermissions), Opus 5.5 at xhigh effort, in a folder under `~/Documents` (`JOBS_CLAUDE_ROOTS`), with photo/screenshot uploads. `JOBS_CLAUDE_CHAT=off` is the kill switch. A reply runs as a child of the service, so restarting the service from inside a page reply kills it.
- **AI ranking** (`backend/ai_pick.py`, `backend/ranking_accounts.py`) shows how the service runs Claude or Codex on the user's Personal or Work **subscription** login, never an API key. Any new LLM call must follow the same rule.
- **resume-tailoring skill**: Claude copy at `~/.claude/skills/resume-tailoring/` (SKILL.md, research-prompts.md, matching-strategies.md, branching-questions.md, multi-job-workflow.md, latex-output.md); Codex copy at `~/.codex/skills/resume-tailoring/` plus `~/.codex/skills/resume-builder/`, each with a `local-cv-setup.md` describing the local LaTeX layout and rules (installed 6 Nov 2026).
- **CV sources**: master `~/Documents/cv-refactor/latex/cv.tex` + `plushcv.cls`, built with Tectonic via `latex/build.sh`; hand-maintained text companion `~/Documents/cv-refactor/Bogdan-Gherghina-CV.txt`. One-page, two-column plushcv layout must be kept. The app serves the main CV from gitignored `cv/` via `GET /cv` (authenticated bytes, blob download on the web).
- **Where tailored CVs go**: `~/Documents/jobs-manager/cv/tailored/<Company>/<Role>/Bogdan-Gherghina-CV.pdf` (fixed recruiter file name), with cv.tex, the unchanged class, preview.png, Report.md, Changes.diff, extracted.txt. Twin Harbour Interactive and LSEG folders already exist there.

## Files and Code Sections

- `backend/claude_chat.py`: chat sessions, roots under `~/Documents`, the `claude -p` command line (around lines 185-195), the phone system prompt `PHONE`, image uploads.
- `lib/claude_chat.dart`: the Claude page UI (chat list, streaming replies, photos, web paste via `lib/paste_web.dart`).
- `backend/service.py`: HTTP routes (`/claude/...`, `/cv`, `/applied`, `/search/latest`), token check, `cv_file()` / `download_name()`.
- `lib/main.dart`: job details sheet (where a "Tailor CV" action would sit), top-bar CV button, options.
- `lib/downloads*.dart`, `lib/api_download_*.dart`: native save-to-Downloads vs web blob download.
- Durable rules to read before writing any CV content (in the base session's `.cs/memory/`): `feedback_cv_style.md`, `user_work_facts.md`, `user_no_react.md`, `feedback_cv_no_fieldwork.md`, `project_cv_pdf_text.md`.

## Problem Solving

- Facts must never be inflated: no React or PHP experience claims, no EC2/SES/CCU, never call the thesis deployed, "AI code review" not peer review, Fieldwork stays off the CV unless the user agrees. Qualitative impact, no exact figures; two columns; AI skills last; safe-refactoring/DORA first and Jest last in the eRepublik bullets.
- PDF text: Source Sans headings needed `WordSpace=1.3` in plushcv.cls; never `XeTeXinterwordspaceshaping` (segfaults Tectonic). Check every build for one A4 page and full text extraction (pdftotext -raw).
- Running the skill end to end is long and interactive (research, branching questions, LaTeX build); a phone UI needs progress, cancel, and a way to answer the skill's questions.
